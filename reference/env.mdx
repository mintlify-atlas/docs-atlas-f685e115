Arcature reads configuration from environment variables at startup. The generated application's `.env` file (in the project root, loaded by the scaffold's `bootstrap/app.rs`) holds all of them. Variables that are absent or malformed are skipped rather than fatal where documented — a stale `PORT=` in a `.env` file does not stop the server booting.

The `.env.example` shipped by `arc new` is reproduced below as the canonical starting point. Values with `__PLACEHOLDER__` are filled in by the generator.

```bash
APP_NAME=my-app
APP_ENV=development
APP_PORT=1183
APP_BIND=127.0.0.1
APP_URL=http://127.0.0.1:1183
APP_KEY=

DATABASE_URL=sqlite://storage/my-app.sqlite?mode=rwc
REDIS_URL=

STORAGE_ROOT=./storage
MAIL_URL=smtp://127.0.0.1:1025
MAIL_FROM=noreply@localhost
```

## Application Identity

### `APP_NAME`

The application name. Appears on the startup banner and in log output. Display and logging only — no runtime behaviour is keyed off it.

```bash
APP_NAME=my-app
```

### `APP_ENV`

The environment name (`development`, `production`, `test`, or any string). Carried by `AppConfig` and readable through `Application::config()`, but **deliberately barred from gating runtime behaviour**.

Every protection that would plausibly key off this — security headers, HSTS, release error redaction, the UAG endpoint — instead keys off `cfg!(debug_assertions)`, which is decided at compile time. An `APP_ENV` variable that could switch protections off would let anyone who can set environment variables downgrade a production binary without redeploying it.

```bash
APP_ENV=production
```

### `APP_URL`

The externally reachable base URL. Used to build absolute links in outgoing mail, signed URLs, and anywhere else a link must be constructed with no request in scope. The application cannot infer this from a request behind a reverse proxy.

```bash
APP_URL=https://app.example.com
```

Access in code: `AppConfig::absolute_url("/password-reset/token123")` joins `APP_URL` with the path, normalising the trailing slash. Passing something that looks like its own URL produces a path segment under the configured host, not a redirect to another origin.

### `APP_KEY`

A 64-byte application secret, base64-encoded. Used to sign sessions and CSRF tokens (via subkey derivation — the raw key never reaches an algorithm directly). Generate with `arc key:generate`. **Never commit the real value.**

```bash
APP_KEY=base64encodedvalue...
```

The application refuses to start without a valid `APP_KEY` when the `auth` feature is enabled. `arc new` mints the key automatically through the same `arc key:generate` logic.

## Ports and Binding

### Port resolution priority

The listen port is resolved at startup by checking these variables in order. The first that parses as a valid `u16` wins; a variable that is present but empty or non-numeric is skipped.

| Priority | Variable | Set by |
|---|---|---|
| 1 (highest) | `ARCATURE_BACKEND_PORT` | `arc dev` / `arc serve --port` |
| 2 | `PORT` | Hosting platforms (Fly.io, Render, Railway) |
| 3 | `APP_PORT` | Application's own `.env` |
| 4 (lowest) | builder default | `.port(n)` or hardcoded `3000` |

`ARCATURE_BACKEND_PORT` outranks `PORT` because `arc dev` sets it and its supervisor already owns the single TCP listener. A stale `PORT` in a developer's `.env` would otherwise aim the child process at the address the supervisor holds, failing with a port-in-use error.

### `APP_PORT`

The default listen port, read by `AppConfig::from_env()`.

```bash
APP_PORT=1183
```

### `APP_BIND`

The default bind address. Read by the generated bootstrap alongside `APP_PORT`.

```bash
APP_BIND=0.0.0.0   # expose to network
APP_BIND=127.0.0.1  # loopback only (default)
```

### `ARCATURE_BACKEND_PORT`

Set by `arc serve --port` and by the `arc dev` supervisor to tell the application child which port to bind. Takes priority over `PORT` and `APP_PORT`.

### `ARCATURE_BACKEND_BIND`

Set by `arc serve --bind` to tell the application child which address to bind.

## Database

### `DATABASE_URL`

The database connection URL. Read by `AppConfig::from_env()` and forwarded to `DatabaseConfig::new()`.

```bash
# PostgreSQL
DATABASE_URL=postgres://user:password@localhost:5432/myapp

# SQLite (created on first connect)
DATABASE_URL=sqlite://storage/myapp.sqlite?mode=rwc

# MySQL
DATABASE_URL=mysql://user:password@localhost:3306/myapp
```

The `mode=rwc` SQLite suffix is important — it tells SQLx to create the database file if it does not exist. Without it, a first connect to a non-existent file fails.

`arc migrate`, `arc db:seed`, `arc db:fresh`, `arc db:reset`, and `arc queue` all fall back to this variable when `--dsn` is not passed.

## Cache

### `REDIS_URL`

The Redis/Valkey connection URL. When empty or unset, the application runs with no cache — nothing connects, nothing times out. The generated `bootstrap/app.rs` wires the cache when this is set.

```bash
REDIS_URL=redis://127.0.0.1:6379
REDIS_URL=redis://:password@127.0.0.1:6379/0
```

## Storage

### `STORAGE_ROOT`

The filesystem root for the default local storage disk. Used by `StorageConfig::fs()` in the generated bootstrap.

```bash
STORAGE_ROOT=./storage
```

## Mail

### `MAIL_URL`

SMTP connection URL in lettre's format.

```bash
MAIL_URL=smtp://127.0.0.1:1025                      # local relay (MailHog, etc.)
MAIL_URL=smtps://user:password@smtp.example.com:465  # TLS
MAIL_URL=smtp://user:password@smtp.example.com:587   # STARTTLS
```

### `MAIL_FROM`

The default `From` address for outgoing mail. Passed to `Mail::from_str()` in the generated bootstrap.

```bash
MAIL_FROM=noreply@example.com
MAIL_FROM="My App" <noreply@example.com>
```

## Development Server

### `ARCATURE_VITE_IPC`

Set by `arc dev` to the path of the Vite IPC endpoint (a Unix domain socket on Linux/macOS, a named pipe on Windows). Read once at pipeline assembly by the dev proxy. In production this variable is unset; the dev proxy is inactive and the asset resolver falls back to the hashed Vite manifest.

```bash
# Example value (set automatically by arc dev, not hand-configured)
ARCATURE_VITE_IPC=/tmp/.arcature/vite-abc123.sock
```

Never set this manually — it is an internal IPC address minted fresh on each `arc dev` invocation and valid only for its lifetime.

## Observability

### `RUST_LOG`

Controls the `tracing` filter. Uses the `tracing-subscriber` Targets syntax: `target=level` pairs, comma-separated.

```bash
RUST_LOG=info
RUST_LOG=arcature=debug,tower_http=trace
RUST_LOG=warn,my_app::controllers=debug
```

Log levels: `error`, `warn`, `info`, `debug`, `trace`. Spans and events from `tracing` are filtered here before they reach any subscriber (JSON logger, OTLP exporter).

### `OTEL_EXPORTER_OTLP_ENDPOINT`

The OTLP collector endpoint. Read by the `otel` feature's exporter when OpenTelemetry is enabled.

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317   # gRPC
```

Requires the `otel` feature. Without it this variable is ignored. The Prometheus text endpoint (`/metrics`) is provided by the `observe` feature independently of `otel` and requires no environment configuration.

<Tip>
  SMTP credentials should not be put in `MAIL_URL` in production. Use a secrets manager and reference the credential from code, or use a transactional mail service that accepts API keys through a different mechanism. The `lettre` `Credentials` type has a `Debug` implementation that prints only the type name — it cannot be accidentally logged.
</Tip>
